# Especificações do Dim

Uma especificação (spec) descreve o comportamento esperado de uma experiência antes de desenhá-la ou implementá-la. Ela conecta o problema observado a critérios que podemos verificar.

## Como trabalhamos

1. Escolhemos um recorte pequeno e descrevemos o objetivo da pessoa usuária.
2. Separamos evidências da pesquisa, hipóteses e decisões de produto.
3. Escrevemos cenário, fluxo, regras, estados e critérios de aceite observáveis.
4. Exploramos a interface no Paper e implementamos com Codex, usando a spec como referência.
5. Registramos o que aprendemos em [validação](../validation/README.md) e atualizamos a spec quando uma decisão mudar.

A spec não precisa definir o layout final nem fingir certeza onde ainda há uma hipótese. Numere cada experiência para ligar sua spec, design, implementação e validação. O primeiro recorte planejado é o check-in do almoço.
